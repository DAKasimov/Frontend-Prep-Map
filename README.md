# Frontend Prep Map

Личная карта фронтенд-разработчика: 18 шагов обучения и 2 дополнительных блока (софт-скиллы, live coding), чек-листы со ссылками на русскоязычный MDN, практические задачи, повторение прошлых тем и вопросы с собеседований с таймкодами на видео.

Весь прогресс (отметки, статусы вопросов, заметки, свои пункты, ссылки на пет-проекты) хранится в `localStorage` браузера. Бэкенд не нужен. Прогресс можно выгрузить в JSON и загрузить обратно через меню «⋯».

## Запуск локально

Нужен Node.js 20+.

```bash
npm install
npm run dev       # дев-сервер с hot reload
npm run build     # сборка в папку dist
npm run preview   # просмотр собранной версии
```

## Публикация на GitHub Pages

В проекте уже есть workflow `.github/workflows/deploy.yml`: он собирает сайт и публикует его при каждом пуше в `main`.

1. Создайте репозиторий на GitHub (например, `frontend-prep-map`).
2. Запушьте проект:
   ```bash
   git init
   git add .
   git commit -m "Frontend Prep Map"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/frontend-prep-map.git
   git push -u origin main
   ```
3. В репозитории откройте **Settings → Pages** и в поле **Source** выберите **GitHub Actions**.
4. Дождитесь зелёной галочки во вкладке **Actions**. Сайт будет доступен по адресу `https://<ваш-логин>.github.io/frontend-prep-map/`.

В `vite.config.js` задан `base: './'`, поэтому сборка работает под любым именем репозитория и на собственном домене без правок. Если нужен абсолютный путь, соберите так: `BASE_PATH=/имя-репо/ npm run build`.

> Прогресс в `localStorage` привязан к адресу сайта. Прогресс из локальной версии не появится на GitHub Pages автоматически: перенесите его через «Экспорт» и «Импорт».

## Структура

```
index.html            разметка страницы
src/main.js           логика интерфейса
src/data.js           данные карты: шаги, чек-листы, практика, повторение, вопросы

public/favicon.svg    иконка

```

## Как редактировать содержимое

Всё содержимое лежит в `src/data.js`, формат описан в комментарии в начале файла.

- **Пункт чек-листа:** `'Текст'` или `['Текст', [['подпись', 'url']], 'Краткий ответ']`. Префикс `+` помечает пункт как новый, суффикс ` *` — как необязательный.
- **`practice`:** массив строк с практическими задачами. Они учитываются в прогрессе.
- **`review`:** вопросы на повторение прошлых тем в формате `['Вопрос', 'Ответ']`.
- **`interview`:** вопросы с собеседования в формате `{ id, q, hint, src, t, also }`. Поле `src` — ключ из `videos` (`v1`, `v2`) или `own`. Поле `t` — секунды или строка `'чч:мм:сс'`.

Не меняйте порядок существующих пунктов и `id` вопросов, иначе сохранённые отметки съедут. Новые пункты добавляйте в конец списков.
